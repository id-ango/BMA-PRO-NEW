- ✅ Submit transaction

## 🎯 HOW IT WORKS NOW

### User Flow for Partial Sales:

```
1. User opens "Add Transaksi Order Jual" page
   ↓
2. Selects P/I (SO) with 3 items (Qty: 5, 3, 2)
   ↓
3. UI loads items in editable table:
   - Item 1: Qty [5] (with "Sisa (Max): 5" badge)
   - Item 2: Qty [3] (with "Sisa (Max): 3" badge)
   - Item 3: Qty [2] (with "Sisa (Max): 2" badge)
   ↓
4. User edits quantities for PARTIAL sale:
   - Item 1: 5 → 2 (sell only 2 of 5)
   - Item 2: 3 → 3 (sell all 3)
   - Item 3: 2 → 0 (don't sell this item)
   ↓
5. Validation checks:
   ✅ All qty > 0 (Item 3 = 0 fails validation!)

6. User fixes: Item 3 = 2 → 1
   ✅ All qty valid
   ✅ All qty ≤ max
   ↓
7. Submit transaction
   ↓
8. Backend calculates total: 2 + 3 + 1 = 6 qty sold
   ↓
9. SaveOrderAktif(noLpb, 6):
   - Original SO qty: 5 + 3 + 2 = 10
   - Sold qty: 6
   - Remaining: 4
   - Status: "1" (Partial)
   - QtyTerima: 6
   ↓
10. Transaction created ✅
11. SO remains active for future sales ✅
12. Next transaction can sell remaining 4 qty ✅
```
